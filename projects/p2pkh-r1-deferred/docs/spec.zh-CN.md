# P2PKH-R1-Deferred 付款脚本规范

开发者征求意见稿 · [English](spec.en.md)

## 付款与启用

付款方根据金额 `v` 和收款人的 65 字节 X9.63 P-256 公钥 `Q`，用原有 P2PKH-R1 模板构造 `S(Q)`。短锁保存公钥、`SHA256(S(Q))`、金额及完整目标输出的承诺 `HASH256(TxOut(v, S(Q)))`。`TxOut` 按线上格式序列化为 8 字节小端金额、脚本长度 CompactSize 和脚本字节。`HASH256` 为双 SHA-256。

钱包可用公开公钥筛选候选输出。接收时必须用实际输出金额和规范模板重建短锁，逐字节核对脚本，并独立比对预期公钥和付款金额。节点执行交易承诺。公开公钥与脚本指纹的语义由收款钱包独立确认。同一公钥重复使用时，短锁可被直接关联。

## 创建与识别输出

偏移从原始锁定脚本的第一个 opcode 起算。以下区间右端不含。

| 字段 | 区间 | 编码 |
|---|---|---|
| 版本标记 | `[1, 9)` | ASCII `R1DEFER` 加 `0x01` |
| 收款公钥 | `[10, 75)` | `04 || X_BE32 || Y_BE32`，必须是 P-256 曲线上的有效点 |
| 目标脚本指纹 | `[76, 108)` | `SHA256(S(Q))` |
| 输入金额 | `[139, 147)` | 8 字节小端金额 |
| 目标输出承诺 | `[166, 198)` | 完整 `TxOut` 的 `HASH256`，拒绝全零 |

锁定脚本为 **801 字节**，序列化 `TxOut` 为 **812 字节**。把四个可变字段置零后计算 SHA-256，得到固定字节指纹 `844eaecb0dc475389c5c3012042d98792243dc6eb84eea78bd7dc3bc4dd28cf6`。识别必须进一步重建并比较整份短锁。 [规范字节](../template/template.hex) · [字段与公开向量](../template/layout.json)

## 花费短锁

启用输入 `i` 必须在输出 `i` 创建等额的承诺目标。锁在内部生成 PUSHTX 签名并调用原生 `OP_CHECKSIG`，将原像与实际交易绑定。固定使用 BIP143 ForkID SINGLE `0x43`，最后执行的 `OP_CODESEPARATOR` 后只有 `OP_CHECKSIG`，序列化 `scriptCode` 为 `01 ac`。锁核对输入金额和 `hashOutputs`，并拒绝缺少配对输出时的全零值。解锁数据是单个 **158 字节**原像的推送，合计 **160 字节**。 [原像与解锁向量](../template/activation-single.json) · [锁定脚本汇编](../reference/asm/lock.asm)

同一交易可启用多个短锁。钱包先确定每个输入与输出的同索引配对，再附加手续费输入和找零，最后为每个启用输入生成原像。第三方可以支付手续费并启用。钱包应跟踪实际生效的启用交易及其输出索引。后续花费按原有 P2PKH-R1 流程，由收款人的外部 R1 签名器授权。 [P2PKH-R1 规范](../../p2pkh-r1/docs/spec.zh-CN.md)

对每份最终启用的资金，延迟路径比直接付款增加一个 812 字节 funding 输出和一个 201 字节启用输入。公共交易字段、额外手续费输入和找零另计。节点与矿工的转发、费率及出块政策需要实测。
